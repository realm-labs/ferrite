## Leaf rule `ITM-POTTERY-SHERD-001` — Pottery sherds are plain items whose identities select pot faces and archaeology acquisition

**Parent:** `PLY-005`, `ITM-001`, `ITM-003`, `ITM-004`, `ITM-006`, `ITM-007`, `ENT-001`,
`WGEN-003`, `CLI-001`, `CLI-006`

**FidelityClass:** `ExactObservableBehavior`

**EvidenceStatus:** `Confirmed`

**SourceConclusion:**

`SourceSpecified` — locked item registration/components, decorated-pot pattern bootstrap and recipe,
tags, archaeology loot, trial-chamber templates/pools, advancements and client assets close all 23
pottery-sherd item identities. Their shared base-item operations retain generic owners.

**Applies when:**

A scoped stack is created, stored, crafted into or recovered from a decorated pot, generated by
archaeology, admitted to either sherd advancement, persisted, reloaded or projected.

Each full item identity is `<name>_pottery_sherd`. All 23 are direct `Item` instances with maximum
stack size 64, uncommon rarity and otherwise ordinary default components. They have no custom use,
use-on, inventory-tick, consumption, durability, equipment, projectile or crafting-remainder hook.
The pattern registry order, item protocol order and Ingredients-tab order are the table order.

**Transition and ordering:**

#### Pot ingredient, face and recovery mapping

`decorated_pot_sherds` contains exactly all 23 identities. Its data order is the first eight table
rows, then friend/heart/heartbreak/howl/miner/mourner/plenty/prize/sheaf/shelter/skull/snort, then
flow/guster/scrape. `decorated_pot_ingredients` contains brick followed by that complete tag.
Reloaded membership selects recipe and advancement matching; the direct identity-to-pattern mapping
remains the code-built registry order tabulated above.

The special decorated-pot recipe accepts exactly four ingredient members at top, left, right and
bottom center. It records them as back, left, right and front faces and produces one pot; the
brick-only shaped recipe instead produces the all-blank default. A sherd contributes only its exact
same-named face pattern. Generic match allocation, consumption and output placement remain
`ITM-RECIPE-001`/`ITM-CRAFT-001`; face ordering, tooltip order, rendering and pot components remain
`BLK-DECORATED-POT-001`.

Cracking a decorated pot emits four unit ingredient stacks in stored back/left/right/front order:
each scoped face returns its exact sherd and each blank face returns brick. An uncracked break
returns the decorated-pot item with face identities instead. Thus shattering recovers sherds but
does not manufacture a different identity; tool/projectile admission and stored-content ejection
retain the decorated-pot and break owners.

#### Archaeology acquisition

Each archaeology table makes one roll using its same-named random sequence:

- `desert_pyramid` has eight weight-one entries. Archer, miner, prize and skull therefore each have
  probability `1/8`;
- `desert_well` has total weight eight. Arms-up and brewer each have weight two and probability
  `1/4`;
- `ocean_ruin_cold` has total weight 15. Blade, explorer, mourner and plenty each have weight one
  and probability `1/15`;
- `ocean_ruin_warm` has total weight 15. Angler, shelter and snort each have weight one and
  probability `1/15`;
- `trail_ruins_rare` has twelve equal entries. Burn, danger, friend, heart, heartbreak, howl and
  sheaf each have probability `1/12`.

Every selected sherd entry emits one default stack of count one. Structure/feature owners decide
which suspicious block receives which table and seed; `BLK-BRUSHABLE-001` owns ten accepted
strokes and item exposure, while `ITM-LOOT-001` owns weighted selection and emission.

Flow, guster and scrape have no direct loot entry. Trial chamber `decor` has total weight 45 and
selects `flow_pot`, `guster_pot` or `scrape_pot` at weight one each. Each rigid template contains
one corridor-loot decorated pot whose four faces contain one matching sherd and three blanks.
`intersection/intersection_2` additionally contains one pot with a flow face and three stored
string. No other locked structure template contains a pottery-sherd item ID. Jigsaw choice,
placement, NBT loading and loot seeding remain `WGEN-JIGSAW-TRIAL-CHAMBERS-001`; a player obtains
the fixed sherd only through the pot's cracked-drop branch.

No recipe, furnace, trade, mob drop, ordinary chest table or other bundled nonblock loot directly
emits a scoped identity. None is fuel or compostable.

#### Advancement joins

`salvage_sherd` has two ANDed requirement groups. The first is an OR over generation of
`desert_pyramid`, `desert_well`, `ocean_ruin_cold`, `ocean_ruin_warm`, `trail_ruins_common` or
`trail_ruins_rare` container loot. The second requires inventory possession of any live
`decorated_pot_sherds` member. The two events need not be the same archaeology result: common
trail-ruins loot plus a trial-chamber sherd can satisfy the pair.

Its child `craft_decorated_pot_using_only_sherds` listens for recipe ID `decorated_pot` with four
separate ingredient predicates, each requiring the live sherd tag. Brick in any face therefore
fails the criterion even though the recipe succeeds. Both advancements send telemetry. Generic
listener registration, requirement completion, persistence and reward publication remain
`ITM-ADVANCEMENT-001`.

**Client projection:**

Every item definition directly selects one like-named generated model and texture; there is no
special renderer, tint or family tooltip. Uncommon rarity supplies the ordinary name style.
Ingredients orders all 23 after Guster Banner Pattern and before Netherite Upgrade Smithing
Template in the table/registry order, with normal parent/search visibility.

Each identity separately maps to the same-named
`textures/entity/decorated_pot/<name>_pottery_pattern` sprite when stored as a pot face. Brick,
missing and unrecognized face identities use the blank side. The pot renderer and component
tooltip ordering remain `BLK-DECORATED-POT-001`.

**Branches and aborts:**

All 23 identities; tag present/removed and ingredient position; special/simple/malformed recipe;
cracked/uncracked and sherd/blank face; all five archaeology tables and every weighted outcome;
trial decor special-pot choice and intersection pot; both advancement requirement groups;
parent/search tab context and item-versus-pot-face rendering.

**Constants and randomness:**

Item IDs `1477..1499`; pattern IDs `0..22`; stack maximum `64`; 23 uncommon items; four recipe
positions/faces; archaeology totals `8/8/15/15/12`; trial decor total `45`, with each special pot
weight `1`. Loot and jigsaw selection consume their owning RNG streams; the items and code-built
pattern map consume none.

**Side effects:**

Recipe inputs/result component, cracked pot drops, archaeology output, player inventory,
advancement state/telemetry and client item/pot-face projection. Base-item use itself has no
family-specific mutation.

**Gates:**

Exact item identity; live sherd/ingredient tags; decorated-pot recipe position and crack state;
installed archaeology table and loot choice; trial-chamber pool/template placement; advancement
loot-history plus inventory predicates; client resource and tab context.

**State read/written:**

Reads stack identity/count/components, tag and recipe/loot/advancement snapshots, pot face
components/crack state, worldgen template/pool selection and client resources. Writes ordinary
stacks, pot decorations/result, loot/drop/inventory state, advancement progress and projection.

**Failure behavior:**

A removed tag member no longer matches the special recipe or sherd predicates; an invalid grid
does not craft; uncracked break preserves the face in a pot item instead of emitting the sherd;
loot nonselection emits another table result; failed suspicious-block or template placement cannot
create its scoped acquisition; a sherd without prior qualifying loot or qualifying loot without a
sherd leaves `salvage_sherd` incomplete.

**Persistence boundary:**

Ordinary scoped stacks persist count and generic components. A pot persists sherd identities in
its ordered decoration component; acquisition provenance, loot/jigsaw RNG and recipe transaction
do not persist. Advancement criteria persist independently, allowing its two requirement groups
to complete at different times. Data reload replaces tags, recipe, loot and advancement snapshots
without rewriting existing sherd stacks or pot faces; registry pattern mapping and item defaults
stay code-built, while resource reload replaces item/pot-pattern assets.

**Boundary cases and quirks:**

Tag order differs from registry/creative order because flow, guster and scrape are appended last in
the tag. A sherd is a plain item despite selecting a unique pot texture. Flow/guster/scrape are
absent from all loot tables and first enter survival through fixed decorated-pot NBT. The salvage
advancement requires both archaeology-table history and current sherd possession, but does not
require that the possessed sherd came from that loot event. Brick can craft a decorated pot but
prevents the all-sherd child criterion.
