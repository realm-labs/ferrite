## Leaf rule `BLK-AMETHYST-BLOCK-001` — Amethyst block joins projectile chimes, crystal footsteps, sculk resonance and geodes

**Parent:** `BLK-001`, `BLK-002`, `BLK-003`, `BLK-004`, `BLK-005`, `RED-001`, `RED-003`,

**FidelityClass:** `ExactObservableBehavior`

**EvidenceStatus:** `Confirmed`

**SourceConclusion:**

`SourceSpecified` — the locked registration and `AmethystBlock` override, entity footstep and sculk-
resonance consumers, reports, complete direct data and class-reference searches, geode owner, all
1,212 decoded structure templates and client assets exhaust this identity's behavior and
projection.

**Applies when:**

`minecraft:amethyst_block` is placed, written, walked on, hit by a projectile, queried beside an
activating sculk sensor, mined, exploded, crafted, selected as sulfur-cube content, generated by an
amethyst geode, serialized or rendered.

**Authoritative state:**

Amethyst block is a property-free `AmethystBlock` with no block entity and sole state `23402`.
Its locked block protocol ID is `978`; its item raw ID is `115`. Registration selects map color
`COLOR_PURPLE`, requires a correct tool for drops, sets destroy speed and explosion resistance to
`1.5/1.5`, and selects the `AMETHYST` sound type at volume/pitch multipliers `1/1`. That sound type
uses the five exact `block.amethyst_block.{break,step,place,hit,fall}` events. The state retains the
default `HARP` instrument, unit selection/collision/occlusion shapes, emission zero, light
dampening 15, friction `0.6`, speed/jump factors `1`, solid redstone conduction, normal piston
reaction, full sturdy faces and no random ticking.

Its direct block tags are exactly `crystal_sound_blocks`, `mineable/pickaxe` and
`vibration_resonators`. No locked incorrect-tier tag names it, so every pickaxe tier is correct for
drops and non-pickaxe tools are not. The matching ordinary block item is common, stacks to 64 and
has only the standard block-item identity/model/name components. It is a direct
`sulfur_cube_archetype/slow_bouncy` item member.

**Transition and ordering:**

#### Projectile chime

After generic projectile collision admits the block callback, `AmethystBlock#onProjectileHit`
does nothing on the client logical side. On the authoritative side it reads the hit block position
and emits exactly one `block.amethyst_block.chime` sound in the `BLOCKS` category, with no excluded
source, volume `1` and pitch `0.5 + nextFloat()*1.2`. Thus the pitch is at least `0.5` and strictly
below `1.7`, and the level RNG consumes exactly one float per admitted hit. Projectile collision,
deflection, removal, damage and packet delivery retain their projectile and sound-family owners;
this override changes no block state and emits no game event.

#### Ordinary and crystal footsteps

The generic entity walking path first emits the ordinary `AMETHYST` step sound, then tests the live
`crystal_sound_blocks` tag. That tag has exactly two locked members: amethyst block and budding
amethyst. This leaf owns the former membership; the generic entity owner retains the shared state
machine and budding amethyst retains its own content audit.

For a tagged supporting state, the extra chime is admitted only when
`tickCount >= lastCrystalSoundPlayTick + 20`. On admission the entity computes
`I = min(1, oldI * 0.997^(tickCount-lastCrystalSoundPlayTick) + 0.07)`, consumes one entity-RNG
float `r`, and emits `block.amethyst_block.chime` through the entity sound route with pitch
`0.5 + I*r*1.2` and volume `0.1 + I*1.2`; it then stores the current tick as the last-play tick.
Rejected intervening footsteps still make their ordinary step sound but neither update the crystal
fields nor consume the extra random draw. The intensity and last-play tick are transient entity
fields, are absent from entity save data, and restart from zero on reconstruction; a reconstructed
entity therefore cannot pass the initial last-tick gate before tick 20.

#### Sculk resonance

When a sculk sensor activates with vibration frequency `1..15`, its existing activation owner
iterates all six adjacent directions. Every neighboring state in `vibration_resonators` independently
emits the matching `resonate_1` through `resonate_15` game event at that neighbor using the
activating entity and resonator state as context, then emits one
`block.amethyst_block.resonate` sound there in the `BLOCKS` category at volume `1`.

The pitch is `NoteBlock.getPitchFromNote(n)` using the 16-entry note table
`[0,0,2,4,6,7,9,10,12,14,15,18,19,21,22,24]` indexed by frequency; index zero is retained by the
source table even though ordinary vibration frequencies are `1..15`. The loop does not stop after
the first resonator, so zero through six amethyst-block neighbors produce the same number of event/
sound pairs. Sensor activation, frequency selection, direction order, scheduled phase changes and
receiver projection remain with `BLK-SCULK-SENSOR-001`; this leaf owns exact admission of state
`23402` through the reloadable tag.

#### Placement, breaking, crafting and loot

Ordinary placement or an authoritative component/geode write commits state `23402`; rotation and
mirror are identity operations. A correct pickaxe admits the block loot table's one roll and one
`amethyst_block` entry behind `survives_explosion`, using random sequence
`minecraft:blocks/amethyst_block`. Incorrect-tool removal reaches no correct-tool loot path, and an
admitted explosion can suppress the entry.

The reloadable processing graph names this identity in exactly one shaped building-category recipe:
a 2-by-2 grid of four `amethyst_shard` items returns one block. The recipe has no group and there is
no reverse block-to-shard recipe. Its advancement has one OR requirement containing
`recipe_unlocked` and possession of an amethyst shard, and grants only this recipe. No other locked
recipe, advancement, trade, non-block loot table or optional built-in-pack record names the block.

#### Sulfur-cube and geode joins

The block item selects the already specified slow-bouncy sulfur-cube archetype. That archetype owns
horizontal/vertical knockback powers `0.4125/0.24`, hit/push sounds, cooldown `0.5`, impulse
threshold `0.05`, and its five attribute modifiers; matching order, equipment, contact and
projection remain with the sulfur-cube owners.

The sole locked amethyst-geode configuration selects state `23402` as its inner-layer provider and
budding amethyst as the alternate provider with probability `0.083`. It fills with air, surrounds
the inner layer with calcite and smooth basalt, and uses the existing geode field, crack,
protection, safe-write and bud-placement transaction. The same-named placed feature applies rarity
`24`, in-square spreading, uniform height from six above bottom through absolute `30`, then biome
filtering. Geode traversal, RNG order, layer thresholds, protected-target handling, ignored write
results and return value remain exhaustively owned by `WGEN-PIPELINE-001`.

An exhaustive scan of all 1,212 locked structure NBT files finds zero amethyst-block palette or
live-cell occurrences. Structure templates are therefore an explicit absence boundary rather than
a second generation source.

**Client projection:**

Chunk and block-update paths publish exact state `23402`; inventory paths project item raw ID
`115` through the configured registry. The client resolves one opaque `cube_all` block model and
the item directly selects that same model without a condition or transform. Ordinary material
sounds, projectile/step chimes, resonance events/sounds, geode terrain and sulfur-cube effects use
their existing packet/effect families; this leaf adds no packet layout or connection state.

Ordinary versus component/geode write; authoritative versus client projectile callback; each

**Constants and randomness:**

State `23402`; block protocol ID `978`; item raw ID `115`; strength `1.5/1.5`; sound multiplier
`1/1`; emission `0`; dampening `15`; friction `0.6`; speed/jump `1`; stack `64`; projectile volume

**Gates:**

**Boundary cases and quirks:**

The projectile chime and crystal-step chime share a sound identity but have different authority,
location, volume, pitch state and RNG owners. Ordinary footsteps occur even while the extra chime
is on cooldown. Resonance is tag-selected rather than an `AmethystBlock` override and can emit from
all six faces in one activation. The block is not decompressed back into shards and appears in no
locked structure template.
