**Authoritative state:**

Cobweb is a property-free `WebBlock` with no block entity and sole state `2247`. Its locked block
protocol ID is `129`; its ordinary block item has raw ID `228`. Registration selects map color
`WOOL`, default note instrument `HARP`, `COBWEB` sounds at volume/pitch multipliers `1/1`,
`forceSolidOn`, no collision, no occlusion, correct-tool-required drops, strength/resistance `4/4`
and piston reaction `DESTROY`. The sound type uses exact events
`block.cobweb.{break,step,place,hit,fall}` at raw IDs `374..378`.

The default interaction/outline shape remains the unit cube while collision and occlusion shapes
are empty. Emission is zero; the block has no state update, scheduled tick, random tick, redstone,
comparator or fluid branch. Forced legacy solidity remains true despite the empty collision cache.
Its sole direct block tag is `fall_damage_resetting`. The item is common, stacks to 64 and has only
the standard block-item identity/model/name components; it has no direct item tag.

**Transition and ordering:**

### Contact, deferred movement and fall reset

After generic inside-block scanning admits `WebBlock#entityInside`, the callback ignores its final
boolean and starts with multiplier `(0.25,0.05000000074505806,0.25)`. A `LivingEntity` currently
holding Weaving instead selects `(0.5,0.25,0.5)`. It then virtually calls
`entity.makeStuckInBlock(state,multiplier)`.

The base entity hook immediately resets fall distance and stores the multiplier; it does not move
the entity at contact time. At the next `move`, a stored vector whose squared length exceeds
`1.0E-7` component-multiplies the requested displacement unless the mover type is `PISTON`, then
clears the stored vector and sets delta movement to zero before edge backing and collision. A
piston move skips multiplication but still consumes the stored vector and clears delta movement.
Repeated admitted contacts can install another vector for a later move.

`Spider#makeStuckInBlock` returns immediately for exact Cobweb instead of calling the base hook.
Spider and inherited Cave Spider therefore receive neither multiplier nor this immediate
fall-distance reset, regardless of Weaving. Other entities, including nonliving entities, use the
ordinary vector; only living entities can select the relaxed Weaving vector.

Independently, `fall_damage_resetting` gives Cobweb a full virtual shape for the generic
fall-resetting clip. During movement with nonzero fall distance and actual displacement length
squared at least `1`, the owner traces from the old position for at most eight blocks along the
normalized displacement against tagged blocks and water. Any non-miss resets fall distance before
the movement record and position commit. This crossing path remains applicable even when the
Spider hook suppressed contact behavior.

### Harvest and loot

Correct-tool admission is supplied by direct item components, not a block mining tag. Shears and
every Sword material put an exact Cobweb `minesAndDrops` rule first at speed `15`; no unrelated
tool is correct. An admitted server-side Shears break damages the tool by `1`. A Sword's tool
component damages it by `2` per block and cannot destroy blocks in creative mode.

After the generic break owner has successfully removed the block and admitted the correct tool,
the one-roll alternatives table resolves in order:

- exact Shears returns one Cobweb without an explosion-survival condition;
- otherwise a correct Sword with Silk Touch level at least `1` returns one Cobweb, likewise without
  explosion survival;
- otherwise the correct nonsilk Sword returns one String subject to `survives_explosion`.

An empty hand, another tool, or a Silk-enchanted non-Sword is rejected before `playerDestroy` and
therefore evaluates no Cobweb loot. No path emits XP. Generic block explosions can still evaluate
the table without player correct-tool admission and reach its explosion-conditioned String
fallback; explosion context and decay remain with the generic loot owner.

### Brewing, Weaving contact and death placement

The hardcoded start mix consumes Cobweb as an ingredient: Water becomes Mundane, while Awkward
becomes the sole Weaving potion. The potion has raw ID `43` and contains harmful Weaving effect raw
ID `36` at amplifier `0` for `3,600` ticks. Redstone/Glowstone do not add a long or strong Weaving
record. Effect duration and amplifier do not change either Cobweb-specific effect below.

First, any living holder gets the relaxed contact vector already described. Second, removal of a
living holder with reason exactly `KILLED` runs the server-side Weaving removal hook. Players bypass
`mob_griefing`; every nonplayer requires that rule true. The victim RNG first chooses a target
maximum uniformly from `2..3`, then supplies 15 radius-one cube samples centered on the victim's
block position. Duplicate positions are ignored. A candidate enters the set only when its current
state can be replaced and the block below exposes a sturdy upper face; collection stops on reaching
the sampled maximum.

After collection, the hook iterates the set, offers default Cobweb with flags `3`, ignores each
write result, and emits level event `3018` with data zero at that position even after a failed
write. Non-killed removal, a nonplayer with disabled mob griefing, zero qualifying samples and
duplicates create fewer or no webs. Amplifier is ignored. Event `3018` projects ten poof particles,
each drawing three Gaussian velocities then three uniform in-block coordinates, and a delayed
Cobweb-place sound through the existing client event owner.

### Iron-golem support exception

Villager group summoning uses `SpawnUtil.Strategy.LEGACY_IRON_GOLEM`. Its support predicate rejects
exact Cobweb before the above-cell air/liquid and support-solid-or-powder-snow tests. This explicit
exception prevents forced legacy solidity from making Cobweb a valid support floor; other entity
spawn algorithms retain their own shape and tag predicates.

### Procedural, processed and template generation

The procedural owners join Cobweb in two structures:

- A Mineshaft spider corridor first visits its full X `0..2`, Y `0..1`, Z `0..length` interior
  with threshold `<=0.6`. Every bay then offers eight decorative sites in fixed order: four at
  `bay±1` with probability `0.1`, followed by four at `bay±2` with probability `0.05`. Each
  decorative pass requires an interior target and at least two in-box sturdy neighbors among all
  six directions. The Mineshaft owner retains chunk clipping, RNG sequence and writes.
- Every Stronghold Library invocation consumes one float for each cell in
  X `2..11`, Y `1..4`, Z `1..13`, 520 draws in Y-X-Z order. A value `<=0.07` selects Cobweb, with
  clipping tested only after the draw.

**Boundary cases and quirks:**

Drag is deferred and one-shot rather than applied at contact time, and it zeros delta movement even
when a piston mover bypasses scaling. Spiders suppress the virtual contact hook but not the generic
long-movement tag clip. Weaving both weakens future Cobweb drag and can create Cobweb after death;
amplifier changes neither behavior. Correct-tool admission makes a Silk non-Sword yield nothing
despite the loot table's broad enchantment predicate. Shears/Silk self drops ignore explosion
survival once their alternative is evaluated. The effect emits event `3018` after an ignored failed
write. Stronghold Library consumes all 520 web floats before clipping, while Mineshaft decorative
sites test interior before drawing.
