## Leaf rule `BLK-ANCIENT-DEBRIS-001` — Ancient debris joins fire-resistant items, bastion loot and scattered Nether ore

**Parent:** `BLK-001`, `BLK-002`, `BLK-003`, `BLK-005`, `RED-001`, `PLY-005`, `PLY-006`,
`ITM-004`, `ITM-006`, `ENT-001`, `ENT-005`, `MOB-001`, `ENV-003`, `WGEN-003`, `CLI-006`

**FidelityClass:** `ExactObservableBehavior`

**EvidenceStatus:** `Confirmed`

**SourceConclusion:**

`SourceSpecified` — the locked registration, reports, components, tags, recipes, advancements,
loot tables, configured/placed features, biome lists, an exhaustive structure-template scan and
client assets exhaust ancient debris's identity-specific behavior and projection.

**Applies when:**

`minecraft:ancient_debris` is placed, mined, exploded, damaged as a dropped item, smelted or
blasted, granted by bastion loot, selected by a sulfur cube, generated by either Nether ore path,
serialized or rendered.

**Authoritative state:**

Ancient debris is ordinary property-free `Block` ID `916` with sole state `21819`, no block entity
and one ordinary block item at item ID `109`. Its registration fixes map color `COLOR_BLACK`,
destroy speed `30.0`, explosion resistance `1200.0`, sound type `ANCIENT_DEBRIS`, correct-tool
drops and the default `HARP` note instrument. The sound type has volume/pitch `1.0/1.0` and
break/step/place/hit/fall sound-event IDs `41/42/43/44/45`.

Unspecified properties retain the ordinary full-solid defaults: unit selection, collision,
occlusion and support shapes; emission zero; light dampening 15; friction 0.6; speed/jump factors
1; solid redstone conduction; normal piston reaction; no random tick, fluid or block entity. It is
a direct `mineable/pickaxe` and `needs_diamond_tool` member. The generic correct-tool predicate
therefore admits diamond- and netherite-tier pickaxes, plus custom tools satisfying the same
data-driven rules; a wrong tool can remove the state but cannot produce its block loot.

The common item stacks to 64 and adds
`minecraft:damage_resistant={types:"#minecraft:is_fire"}` to the ordinary block-item components.
The exact locked `is_fire` damage-type closure is `in_fire`, `campfire`, `on_fire`, `lava`,
`hot_floor`, `sulfur_cube_hot`, `unattributed_fireball` and `fireball`.

**Transition and ordering:**

#### Placement, breaking, fire and explosion

Ordinary placement writes sole state `21819`; rotation and mirror are identity operations.
Correct-tool break admission reaches one block-table roll that returns one ancient debris behind
`survives_explosion` and uses random sequence `minecraft:blocks/ancient_debris`. Incorrect tools
remove the block without a drop. Explosion resistance `1200.0` participates in the generic
explosion calculation; it is not a separate hard-immunity branch.

Ancient debris has no `FireBlock` odds entry and is not lava-ignitable, fuel or compostable. Its
placed block therefore has flammability/spread odds `0/0` and burn time zero. Separately,
`ItemEntity#hurtServer` asks `ItemStack#canBeHurtBy` before changing dropped-item health. The
default stack rejects every damage source in the eight-member `is_fire` closure and follows the
generic item-entity damage transaction for other sources. Block explosion resistance and item
damage resistance are independent.

#### Cooking, discovery and advancement

Exactly two locked recipes consume ancient debris and return one netherite scrap with experience
`2.0`:

| Recipe | Serializer | Omitted `cookingtime` default |
|---|---|---:|
| `netherite_scrap` | `smelting` | 200 ticks |
| `netherite_scrap_from_blasting` | `blasting` | 100 ticks |

Both omit a group. `AbstractCookingRecipe#cookingMapCodec` receives the distinct default from the
concrete serializer, so the omitted field does not give blasting the smelting duration. Furnace
input/fuel/result checks, progress reset, XP rounding and result extraction remain with
`ITM-FURNACE-001`.

Each matching recipe advancement has parent `recipes/root`, criteria `has_ancient_debris`
(`inventory_changed`) and `has_the_recipe` (`recipe_unlocked`), one OR-requirement group containing
both criteria, and a reward granting its matching recipe. Direct recipe grant and inventory
discovery are alternative unlock paths.

The separate `nether/obtain_ancient_debris` advancement has parent `nether/root`, one
inventory-changed criterion requiring ancient debris, a singleton requirement, an ancient-debris
icon, localized title/description and `sends_telemetry_event=true`. Possession completes it;
smelting, placing or mining are not additional criteria. Its child advancement does not add a
consumer to this identity.

#### Bastion acquisition and sulfur-cube selection

Beyond block self-loot, five direct entries in three bastion chest tables can emit the item:

| Table, pool | Rolls / direct-entry total weight | Ancient-debris entries |
|---|---|---|
| `chests/bastion_treasure`, pool 0 | 3 / 112 | count 1, weight 10; count 2, weight 4 |
| `chests/bastion_other`, pool 0 | 1 / 89 | count 1, weight 12 |
| `chests/bastion_hoglin_stable`, pool 0 | 1 / 100 | count 1, weight 12; count 2, weight 5 |

Each table uses its namespaced table ID as its random sequence. Entry competition, weighted draw
order, container filling and structure chest placement remain with generic loot and bastion
owners. No other locked loot or trade record directly emits or consumes ancient debris.

The item is a direct `sulfur_cube_archetype/slow_flat` member. That archetype installs
horizontal/vertical knockback powers `0.4125/0.105`, hit/push sounds
`minecraft:entity.sulfur_cube.slow_flat.{hit,push}`, push cooldown `0.9`, impulse threshold `0.03`
and its five locked movement/resistance modifiers. Matching, installation, equipment changes and
contact handling remain with `ENT-KNOCKBACK-001` and the sulfur-cube owners.

#### Scattered Nether ore

Two configured features use `minecraft:scattered_ore`:

- `ore_ancient_debris_large` has size `3`;
- `ore_ancient_debris_small` has size `2`.

Both have one tag-match target, `base_stone_nether`, whose exact closure is netherrack, basalt and
blackstone; the result is default ancient debris and
`discard_chance_on_air_exposure=1.0`. The scattered-ore feature chooses
`attempts=nextInt(size + 1)`, producing `0..3` or `0..2` attempts. For attempt index `i`, it uses
`d=min(i,7)`, consumes six floats in X/Y/Z pairs and rounds each `(first-second)*d` offset. Attempt
zero still consumes all six floats although every offset is zero.

Because the exposure chance is exactly one, the feature consumes no exposure-probability float.
After target admission it rejects the candidate if any of the six neighbors, in
DOWN/UP/NORTH/SOUTH/WEST/EAST order, is air; otherwise it offers the ancient-debris write with flags
`2` and ignores the Boolean result. The feature returns true even with no successful replacement.
Target testing, neighbor reads and writes are per attempt and can revisit a position.

The large placed feature applies `in_square`, a trapezoid absolute-height range `8..24`, then
`biome`. The small `ore_debris_small` placed feature applies `in_square`, uniform height from
`above_bottom=8` through `below_top=8`, then `biome`. Nether wastes, crimson forest, warped forest,
soul sand valley and basalt deltas all list large then small in underground-ores generation step
7. Source-chunk seeding, placement-modifier coordinates, exact height distributions, target-rule
evaluation and biome/chunk publication remain with `WGEN-PIPELINE-001`.

An exhaustive decode of all 1,212 locked structure NBT files finds zero live, palette-only or
jigsaw-final-state ancient-debris cells. No structure processor directly names the identity.

**Client projection:**

Terrain and block-update packets publish block ID `916`/state `21819`; inventory paths publish item
ID `109` and its component snapshot. The unconditional blockstate selects
`minecraft:block/ancient_debris`. That model inherits `block/cube_column`, using
`ancient_debris_top` on the ends and `ancient_debris_side` elsewhere. The item definition directly
selects the block model with no tint, rotation, condition, emissive layer or special renderer.

The Natural Blocks tab places ancient debris after nether quartz ore and before raw iron block.
The Ingredients tab places it after diamond and before quartz. The block is absent from Building
Blocks. Generic opaque-cube face culling, map shading, sounds, note behavior, break particles and
item-component publication retain their existing client/effect owners.

**Branches and aborts:**

Correct versus incorrect tool; surviving versus suppressed explosion loot; block explosion versus
eight fire-tagged and other item damage sources; smelting versus blasting duration; either recipe
unlock criterion; possession advancement; five weighted chest entries; slow-flat admission; large
versus small placed feature; `0..size` attempts; target and six-neighbor exposure rejection;
accepted versus rejected write; zero template cells; and block versus item/tab projection are
distinct.

**Constants and randomness:**

Block/item/state IDs `916/109/21819`; strength `30.0/1200.0`; emission `0`; dampening `15`;
friction `0.6`; speed/jump `1`; stack `64`; five sound IDs `41..45`; cooking experience `2.0` and
times `200/100`; chest rolls, weights and counts as listed; feature sizes `3/2`; attempt ranges
`0..3/0..2`; maximum offset distance `min(i,7)`; six offset floats per attempt; exposure chance
`1.0`; write flags `2`; large absolute Y `8..24`; small height anchors `8/8`. Generic explosion,
loot, furnace and placement owners retain their documented streams.

**Persistence boundary:**

State `21819` persists solely by palette identity and has no block entity. Item stacks persist
their damage-resistant component. Furnace progress and player unlock/advancement state retain
their owning persistence rules. Recipes, advancements, loot, tags, biome feature lists and
configured/placed features rebuild on data reload. Generated cells thereafter persist as ordinary
block states; feature RNG and rejected attempts do not persist or resume.

**Boundary cases and quirks:**

Resistance `1200.0` does not bypass the generic explosion calculation. A wrong tool can destroy the
block but cannot reach self loot. The placed block is neither fire-spreadable nor lava-ignitable,
while the item component separately rejects eight fire damage types. Blasting's omitted
`cookingtime` means 100 ticks, not the smelting default. Both chest count variants are independent
weighted entries. Scattered ore consumes six floats even at attempt zero, consumes no exposure
float at chance one, rejects an otherwise valid target next to any air, ignores failed writes and
still returns success. No bastion template contains an ancient-debris cell; bastion acquisition is
chest-loot-only.
