# Cross-System Ordering Inventory

**Surface:** `SURFACE-CROSS-SYSTEM-ORDERING-001`
**Status:** `Mapped`
**Primary evidence:** `OFF-SERVER-001`; `OFF-REPORT-001`; `EXP-SIM-001`

This inventory closes every unordered pair among the nine non-meta behavior surfaces. Each row owns
admission, same-target order, failure/atomicity, persistence and first client observation. The
machine ledger rejects a missing, duplicate, ownerless or nonterminal pair.

## Global arbitration

1. Authoritative live mutation occurs on the server executor. Network decode, IO, data preparation
   and text/profile work may run elsewhere, but they publish only by queuing a server task or
   crossing an explicitly documented future/barrier. Background completion order is not live-state
   commit order.
2. Server tasks and synchronous callbacks do not interleave. The later admitted operation reads the
   earlier operation's committed state unless its owner explicitly captured an earlier snapshot.
   Fixed tick phases, precollected scheduled batches, selector/target snapshots and reload candidate
   objects are the only broader snapshots; their owners define revalidation.
3. A rejected admission mutates nothing unless its semantic owner names a pre-failure side effect.
   Once an owner commits a write, packet or partial target prefix, no cross-system layer rolls it
   back. Multi-object atomicity exists only where the owner explicitly preflights or stages it.
4. Durable effects dirty and save through their semantic owner. Queues/callbacks are persisted,
   cancelled or reconstructed only where PersistenceReload says so; no packet, parser, iterator,
   callback frame, RNG draw or client mirror is replayed after restart.
5. Projection follows the committing owner's packet/update order. End-of-tick connection and chunk
   sending cannot make a later authoritative value appear before an earlier explicitly emitted
   effect, while prediction correction and protocol acknowledgement retain their own stream order.

## Reproduction

Run `JOIN-01` through `JOIN-36` in both pair orders, plus a rejection/failure order. Instrument the
server executor, phase/callback entry, owner commit, dirty/save admission and packet send points.
For each trace assert:

- one admitted authoritative order and no unowned interleaving;
- the exact owner-specific preflight or retained partial prefix;
- durable state after unload/reconnect/clean restart/crash;
- first client state/effect/acknowledgement order; and
- no replay of transient ingress, parser, callback, RNG or projection state.
